# Database contract

Every model and relation is annotated in `prisma/schema.prisma`. The initial migration creates the model schema; the second migration adds PostgreSQL invariants that Prisma cannot express directly.

## Rules enforced by the database

- Users and newsletter leads have unique, trimmed lowercase emails. Application input validation remains responsible for full email syntax.
- An empty address book is allowed. A nonempty address book must have exactly one default. Update the old default to false, then the replacement to true **in the same transaction**. The existence check runs at commit; the unique index checks immediately. Address writes lock the owning user row. Addresses cannot change owners.
- Money uses exact two-place PKR decimals. Prices, stock and order amounts cannot be negative; quantities must be positive. The order total must equal subtotal + shipping + tax - discount. The discount cannot exceed the merchandise subtotal. These are generic amount fields, not implemented tax calculations.
- An order must contain at least one item and its subtotal must match the sum of quantity × snapshotted unit price at transaction commit. Create the order and items in one transaction/nested Prisma create.
- Order item identity, quantity, descriptions and price are immutable after insertion. Order shipping snapshots are immutable after insertion. Future operational delivery corrections need a separate audited record; they must not rewrite the original purchase snapshot.
- Composite product/variant foreign keys reject a line item referencing another product's variant. Catalog deletion is restricted while referenced by orders. Use draft/inactive status to retire merchandise.
- Payment references are unique per provider when populated. This prevents attaching the same accepted provider transaction to different orders; it does not implement webhook idempotency or refund processing.
- Deleting a user removes saved addresses and clears order/analytics user attribution. Order contact/address snapshots remain; retention and erasure workflows need explicit business policy later. Never put PII, credentials or session tokens in analytics metadata.
- Content is a JSON object; schema version and revision must be positive. Analytics metadata is also a JSON object. Rich-text structure and event-specific metadata validation belong in future write handlers.

## Query and write conventions for later phases

Resolve variant priceOverride ?? product.basePrice once when constructing an OrderItem and persist that Decimal as unitPrice. Copy product name, size and SKU too. Use Prisma Decimal or integer minor-unit arithmetic, never binary floating-point arithmetic for totals. Runtime stock decrements must be conditional and transactional; the nonnegative constraint is only a final guard.

Use status + creation time indexes for catalog/fulfillment lists, user + placedAt for order history, and type/session/user + timestamp for analytics. Page + key identifies content blocks; increment revision with a matching old revision to reject lost updates.

All timestamps use timestamptz. IDs are generated by Prisma using cuid(); SQL clients must supply IDs explicitly. `@updatedAt` is also managed by Prisma; direct SQL administrative writes must supply updated timestamps. SQL checks and triggers still apply to every client.

Country fields store uppercase ISO-style two-letter codes, default PK. PKR-only currency does not by itself decide shipping geography. Product image records support URL, alt text, ordered position and optional dimensions; no images are seeded without genuine assets.
